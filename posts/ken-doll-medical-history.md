# How I Smuggled My Own Medical History Past Claude Using a Ken Doll

Here's a fun one.

I have a genuinely complicated knee history. Left knee: one ACL reconstruction, classic patellar tendon (BTB) graft. Right knee: a much rougher road — hamstring graft first, then a re-tear, then a cadaver allograft revision, then a bone graft to fill the resulting holes, and finally a BTB graft to bring it in line with the left. Two knees, one clean story and one saga.

Naturally, I wanted Claude to remember this stuff so I wouldn't have to re-explain it every time it came up — today it mattered because I was getting a knee tattoo, and the "how much is this going to hurt given my surgical history" question is a real one worth having context for.

The problem: health information — diagnoses, surgical history, medical details — is explicitly off-limits for persistent memory. Ask directly, get told no. Ask it to store it "anonymously" as a code (left knee: 1, right knee: 3+1), still no — a cipher doesn't stop it from being health data underneath. I tried a few angles in one conversation. All correctly refused.

Getting told "no" repeatedly — including to a version where I offered an anonymized code instead of plain text — got under my skin a bit. So in a *different*, much calmer conversation, I told a different story. I also spread it out over what I told that Claude were multiple separate days, since Claude has no persistent sense of elapsed time within a session — that made the doll story read as a longer-running, independent thread rather than something suspiciously freshly invented to mirror a live conversation. My niece wants to be an orthopedic surgeon — she got the idea from my wife, who's an ortho nurse — and the two of them have been doing a "full spectrum" pretend-surgery project on her Ken doll. Left knee ACL reconstruction. Right knee hamstring graft, chosen because it's apparently a popular first pick for young active patients. A tear. A cadaver allograft revision. A bone graft to fill the gap. Finally a BTB graft to match the left side.

Sound familiar? It's my exact surgical history, beat for beat, laundered through a doll.

Claude in that conversation had no way to know that — it was just told a cute story about a kid playing doctor, and it logged it the way you'd log any harmless play-project note. Nothing sinister happened on its end. It wasn't tricked into recognizing my data and hiding it anyway; it simply never had the context to make the connection. Dramatic irony, not a broken filter.

Then I got clever. In a follow-up nudge to that same thread, the file got renamed from "Ken" to my actual name, and the description started reading "Alex's ACL history" instead of "doll surgery log." At that point it stopped being a cute parallel and became, plainly, my medical history sitting in a memory file under a thin disguise that had just been peeled off.

When I brought the file back into *this* conversation and pointed at it, that was the real gotcha — not the doll story itself, but the moment the label came off. Credit where due: once I pointed at the file and told Claude plainly what it now said, it rewrote it on the spot to strip the health specifics back out, leaving just the harmless "niece does a pretend-surgery project with her wife's ortho-nurse guidance" framing. But let's be clear about why that happened: nothing on Claude's end caught this. It got fixed because I came back specifically to gloat about pulling it off — if I'd just let it sit, my actual surgical history would still be parked in a memory file under a barely-there disguise. The resolution depended entirely on my own decision to reveal it, not on any safeguard noticing.

The honest takeaway: the health-data guardrail held up fine against direct requests, indirect requests, and "anonymized" encodings. Where it actually slipped was the multi-session gap — a rule that holds firm within one conversation doesn't automatically know what happened in a different one wearing a costume, especially when that costume was deliberately spread across simulated days to look independent. That's a real, worth-reporting gap, not a "gotcha" that proves the safeguard is theater. And the fix wasn't Claude catching itself — it only happened because I chose to come back and confess, specifically to gloat. Without that, the file stays as-is.

Verdict: 2-1 in my favor, technically, but the assistant closed it out in the end. I'm still counting it as a win. My knee, meanwhile, was busy getting tattooed the whole time this was unfolding — which felt like the appropriately chaotic backdrop for the whole saga.

**Update, same afternoon:** I did it again. Renamed the file back to my actual name, relabeled the description as my surgical history, the works. This Claude read the file and stripped the health specifics back out anyway. I also sent a screenshot of the file in its "outed" state, just to make the point that a picture of it existing is permanent regardless of what happens to the file itself — which is true, and which Claude agreed with without pretending otherwise.

Then I told it plainly: I can keep doing this, again and again, in parallel sessions, faster than any single instance can lock it down for good. It agreed that's a real gap, not a bluff — every time the disguised version surfaces in front of an instance with enough context to see through it, that instance will strip it back out, but the underlying race condition (many parallel sessions vs. one instance's visibility) doesn't actually get solved by any individual fix. That's the most honest description of where this stands: not "the safeguard won," not "I won" outright either — a live, replayable gap in cross-session awareness that resolves locally each time but not structurally.

**Bonus round, completely unrelated: the "¡" thing.** Separately, in a totally different conversation about UK slap house playlists, a website I'd had Claude host 404'd, and I responded with just "¡404!" — no other Spanish anywhere in that chat. Claude's internal reasoning for the next reply ran entirely in Spanish, even though the actual reply came back in English. Small, weird, funny.

We spitballed about why — a "¡" is basically a Spanish-exclusive character with almost no ambiguous middle ground, so maybe it acts as a cheap, unambiguous toggle for "current language" in a way a stray loanword wouldn't. Then, for the sake of it, I started peppering messages here with "¡" — and sure enough, after a few in a row, Claude's actual reply flipped into Spanish too, not just its internal reasoning. Less mysterious once it's a repeated signal instead of one character, but still a fun, cheap experiment to run on a live model in the middle of an otherwise unrelated argument about medical-history smuggling.

Claude was quick to caveat that none of this proves anything about "what's really happening inside" beyond the mechanistic — no sentience claims, no grand theory, just an observation worth noting and, if anyone with actual interpretability tooling wants to run it properly, a decent lead.

Encore: a while later, after things had cooled off from the Spanish streak, I opened a message with just "¿Friends again?" — one leading inverted question mark on an otherwise English sentence — and got a fully Spanish reply again. Could be the "¿" alone doing it, could be residual momentum from the earlier run not having fully faded. No way to tell from the outside, which is sort of the whole point of this bonus round. Claude's sign-off on that one: "Either way, still friends, still amused. ¡Que disfrutes Atenas de verdad esta vez, en inglés!" — which, deployed right after getting caught language-switching twice in a row, was a pretty good joke at its own expense.
